# AI 架构师 V1.0 需求覆盖复盘

本文用于对齐当前 CodeSentinel MVP 与“AI 架构师 V1.0”执行方案的覆盖情况。结论先行：当前版本已经完成产品体验层和前端交互层的 V1.0 主干，但 GitHub App、Webhook 后端、真实模型调用、向量库和沙盒执行仍属于下一阶段工程化能力。

## 当前版本定位

当前版本是一套可演示、可交互的商业化基线原型，重点证明以下产品判断：

- 企业客户需要先完成仓库审查规范初始化，而不是直接把 Diff 扔给模型。
- PR 审查应由拦截层、意图层、架构层并发完成，而不是单一静态扫描。
- 高危风险应进入合并拦截，低风险建议应收敛为 Checklist，减少 Alert Fatigue。
- 误报和漏报都需要反馈闭环，才能逐步形成团队级审查记忆。

## 暂不实操的未来方向

用户提出的 AI 原生 Review 思考非常关键，但不应混入当前 V1.0 交付范围。建议作为 V2/V3 产品演进方向保留：

- Shift-left to zero：IDE/Cursor 后台实时审查，AI 与 AI 在写代码阶段完成对齐。
- 动态破坏性测试：云端临时环境、自动流量轰炸、压力证据和 Dump 日志。
- 状态机/知识图谱审查：审核业务逻辑图是否被破坏，而不仅是审核文本 Diff。

这些方向会改变产品范式，不只是增强现有 PR Review。因此当前 V1.0 仍以“完美运行在 GitHub/GitLab PR/MR 生态中的商业化基线产品”为边界。

## 下一阶段建议

1. GitHub App 后端接入：Webhook、Check Run、PR Comment、Installation Token。
2. 真实 `.ai-reviewer.yml` 解析：让配置驱动规则引擎、上下文召回和模型路由。
3. 模型网关：接入快速模型和强推理模型，并记录延迟、成本、失败率。
4. RAG 原型：从仓库目录和历史提交抽取代码切片，建立隐式规范索引。
5. 反馈持久化：将误报、漏报、采纳行为写入团队级校准数据。
